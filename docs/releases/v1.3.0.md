# Easy Edge Apps 1.3.0

A normal per-user Windows installation, saved preferences, and optional update notifications, with the portable script still available.

## What's new

- **MSI installer:** The x64 per-user package adds the Easy Edge Apps manager to Start and Installed Apps without requesting elevation. It supports upgrade, repair, downgrade rejection, and uninstall. Program files are separate from saved website data, which survives upgrade and uninstall.
- **Settings menu:** A gear opens Preferences and update commands. Settings include default Desktop/Start menu placement for the new-website editor, persistent background motion, and 12/14/16/18-point text for setup, its menu, and owned helper dialogs. Save applies changes; Cancel discards them. The main Motion checkbox saves immediately.
- **Update checks:** Check manually at any time, or opt into daily automatic checks when setup opens or preferences are saved. A newer stable release exposes Download update, which opens the official release page. Checks are cancellable and never download or install application code. There is no background service or scheduled task.
- **Private debug logging:** Opt-in local events include fixed operation names, outcomes, timestamps, application/host versions, and exception types. No URLs, notes, passwords, browser content, error messages, or stack traces are recorded. Logs rotate around 256 KiB, retain one previous file, and can be opened or cleared from Settings.
- **Default Edge profile:** Choose a local profile for new websites, including new imports, or let Edge choose. Existing apps retain their profile through editing, opening, import, and repair. Install also accepts an explicit `-EdgeProfile`, including an empty value to restore Edge-controlled selection. Profile identifiers and global preferences do not travel in App Kits.

## Download and upgrade

Choose **EasyEdgeApps-1.3.0-x64.msi** for a normal Windows 11 installation, or **EasyEdgeApps.ps1** for portable use. Both manage the same per-user data. Close setup before upgrading, and run the MSI in the account whose websites you manage. The manager launcher uses built-in Windows PowerShell without a console; website shortcuts still launch Edge directly.

The MSI, launcher, and script are unsigned. Compare downloads with `SHA256SUMS.txt`, review the source, and respect Windows security warnings and organizational policy. Checksums detect mismatched downloads, not publisher identity. Build dependencies are not end-user prerequisites. WiX's complete notices are installed, and **WiX-5.0.2-source.zip** provides the corresponding unmodified source.

Uninstall through Windows Installed Apps to remove only the manager and its Start menu shortcut. Saved website shortcuts, preferences, logs, notes, icons, recovery data, and browser sign-ins are preserved. Remove unwanted websites using the manager before uninstalling it, or reinstall later.

## Safety and compatibility

Automatic update checking and debug logging are **off by default**. The update checker uses the fixed official GitHub HTTPS endpoint without cookies or Windows credentials, rejects redirects before following them, bounds and validates response data, and accepts only official stable release URLs. GitHub can observe ordinary request metadata; no saved app data is sent. Manual download and installation remain separate user actions.

Preferences use strict data-only JSON, existing locking, and atomic replacement. Damaged preferences fall back to defaults with a warning and are replaced only after an explicit Settings save. Only validated local Edge profile identifiers can become launch arguments; arbitrary switches and paths are rejected.

Existing version-1 App Kits, website icons, Favorites import, automation, and ownership/rollback protections remain compatible. The manager is registered as a Windows application; individual website shortcuts are still Edge app windows, not registered PWAs. Keep Windows and Edge updated separately.

Encrypted exports remain experimental and require independent security review before production use. Encryption protects exported kits, not installed settings, logs, shortcuts, or browser sessions. A whole kit is not one atomic transaction, and Check and Repair does not verify website sign-in or availability.

## Verification

Twelve isolated application suites cover both Windows PowerShell 5.1 and PowerShell 7, including strict preferences, profile ownership and CLI routing, log privacy/rotation, fixed-endpoint update requests, cancellation and daily scheduling, Settings save/cancel and damaged-data recovery, and native layouts at 12/18/24 points within 1024 by 768.

Separate MSI checks cover actual per-user installation, upgrade from a synthetic older package, downgrade rejection, script and shortcut repair, installer registration, complete notices, and non-destructive uninstall. A compiled-launcher smoke test checks real STA Windows PowerShell startup without a console or arbitrary forwarded arguments. CI builds and tests the MSI in addition to both application test jobs.

Physical accessibility, the installer wizard on other displays, ARM64, real-site sign-in, cross-computer handover, and OneDrive/network-filesystem behavior still require checks on the intended computers. See the README, installer guide, automation guide, and security guidance for details.
