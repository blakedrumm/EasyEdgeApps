# Easy Edge Apps 1.3.3

Author: Blake Drumm (blakedrumm@microsoft.com)

Adds real Windows-approved taskbar pinning with website-specific window grouping, and fixes the repeated Edge automatic-sign-in/sync popup in fresh sessions.

## Usability and readiness

- Setup grows to fit its realized editor within the current monitor's working area, including saved 12/14/16/18-point text. Small displays retain scrolling; startup focuses the website name and preference changes preserve the active field.
- Preferences cannot clear the Start menu entry while an unsaved website has Taskbar selected.
- High-resolution starfield painting uses fast opaque scaling, clip-aware redraws, and paint-aware frame pacing. On the review machine, synthetic 4K full-tree painting fell from about 576 ms to 51 ms; this is not a guaranteed live frame rate or an input-latency measurement. Existing motion and accessibility behavior remains.
- Icon failures identify blocked requests, missing/unsupported icons, timeouts, and connection failures without exposing server details or replacing the current icon. ChatGPT refused credential-free requests with HTTP 403 during testing; the app explains that refusal and points to local icon selection, without bypassing access controls.
- Check/import details show configured/current/resulting browsing modes without schema changes. Missing-settings folders remain visible and non-repairable, with explicit uncertainty about retained data rather than a guessed removal history.
- Access-denied cleanup of a read-only staging file no longer misreports a completed transaction as failed; the existing completion-marker and retry behavior applies.

No pre-existing source, fixtures, historical MSIs, or build caches were removed. See the [production-readiness review](../Production-Readiness-Review.md) for decisions, evidence, and remaining risks. Encrypted exports still require independent review before production use, and all executables remain unsigned.

## Taskbar apps

Select **Taskbar** beside Desktop and Start menu, save the website, and approve Windows' own pin confirmation. The Start menu entry is required. The pinned website opens as an Edge app window under its saved website icon and identity, without a separate Edge taskbar entry. The manager does not need to stay open.

With **Fresh session each time** off, taskbar apps keep a dedicated profile between launches; sign in once inside the app as needed. Reopening a running app focuses its existing window. Normal Edge profiles are not copied, cleared, or relabeled. With Fresh on, each launch uses an independent Guest profile while its windows share the website's taskbar group.

The checkbox records local intent, not Windows' live pin state. Decline, cancellation, or unavailable pinning keeps the app saved. Native desktop pin requests require a compatible updated Windows 11 shell and remain subject to foreground, notification, policy, and approval restrictions. Unpin using Windows before removing the app or opting out; the tool never silently pins or unpins. Persistent app data is retained after opt-out, removal, and MSI maintenance.

## Guest sessions

Fresh launches now use Edge Guest mode inside their existing independent temporary directories. Guest profiles do not sign into an Edge browser account or sync browsing data. Website sign-in remains available, and normal Edge profiles and shortcuts remain unchanged. Each session still has its own cookies, cache, local storage, browser process tree, and cleanup.

The launcher refuses conflicting browser policies, including disabled Guest mode or forced browser sign-in, without changing policy or falling back to a normal profile. Guest mode does not guarantee anonymity or disable all forms of website/Windows authentication.

## Update existing websites

1. Close the website's fresh windows and the manager, then install **EasyEdgeApps-1.3.3-x64.msi**, or replace the portable script.
2. Open Easy Edge Apps and select **Check apps...**.
3. Select the repairable fresh websites, choose **Repair Selected**, and approve. Saving each website again also rebuilds its launcher.
4. Open the saved website again. Its app-window title now includes **[Guest]**.

Installing the MSI alone does not replace generated per-website launchers. There is no need to remove and recreate websites or change their Fresh setting. Replace older taskbar pins using the new **Taskbar** checkbox, especially pins targeting Edge directly that bypass freshness. Newly saved/repaired Fresh or Taskbar apps use local manifest schema 3 and need 1.3.3 or later. Legacy schema-2 fresh apps remain repairable.

## Verification and limits

The fourteen application suites cover both Windows PowerShell 5.1 and PowerShell 7. Regressions include native shortcut/window identity, confirmed pin results, cancellation and process-inspection failures, conflicting-action guards, stale editor saves, policy rejection, schema-2 repair, import preflight, and retained app data. The real-Edge smoke checks three independent Guest launches with empty cookies/storage/cache and cleanup, and three persistent launches with retained state and single-window reopening.

Additional regressions exercise saved-font startup, small-screen fitting, scaled-pixel opacity and panel alignment, graphics-state restoration, paint-cost feedback, direct/worker/GUI icon failures, read-only staging cleanup, all four Fresh/Taskbar combinations, both kit versions, and ambiguous retained-data folders. New regressions were observed failing before their corresponding fixes.

Interactive acceptance on Windows 11 build 26200.9106 confirmed a real user-approved pin, launch from that pin with matching website identity, one website taskbar icon without a separate Edge entry, and Windows-confirmed removal of the synthetic pin. Browser screen capture is optional and requires foreground access; background GPU captures are not treated as visual proof. MSI lifecycle and main/tag CI are release gates.

Crash, power loss, permissions, or persistent file locks can still leave marked fresh data for later cleanup; it is never reused. Normal profile data, downloaded files, and server-side records are not cleared. Live managed-policy enforcement, other Windows/Edge versions, non-English prompt detection, real-site authentication, physical accessibility, and cross-computer handover still need target-machine acceptance checks.

The script, MSI, and launchers remain unsigned. Verify downloads against **SHA256SUMS.txt**. **WiX-5.0.2-source.zip** and complete notices are included. App Kit formats are unchanged and exclude Taskbar intent, pins, and profiles. Import/repair preserve local Taskbar mode without pin requests; kits removing its required Start entry are rejected during preview. Encrypted exports remain experimental pending independent security review.
