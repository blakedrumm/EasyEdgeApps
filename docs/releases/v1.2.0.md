# Easy Edge Apps 1.2.0

Website icons, command-line automation, and an updated native Windows setup experience in one self-contained PowerShell script.

## What's new

- **Get website icons:** Select **Get icon** to discover raster or static SVG favicons, preview the result, and save it only when you choose **Add website** or **Save changes**. An animated loading spinner covers resolving, downloading, and conversion. Background lookup is cancellable; failures and stale results preserve the current icon. Large images are streamed to temporary storage and resized instead of rejected by a fixed download-size cutoff. Retrieved icons travel with App Kits.
- **HTTPS-first addresses:** Setup accepts a website host without `https://`, probes HTTPS first, and falls back to HTTP after connection failure. Explicit schemes and TLS authentication failures never silently downgrade. The resolved address is shown before saving, and direct HTTP saves require confirmation. Resolution runs in the background with the same spinner; pending saves resume only if the form has not changed.
- **Command-line automation:** `-Unattended` explicitly approves supported operations without setup dialogs or confirmation prompts, preserves validation and `-WhatIf`, returns structured results, and provides explicit success/failure exit codes. Kit import supports selected `-AppNames`; encrypted operations continue to accept caller-managed `SecureString` values only.
- **Built-in help:** `--help`, `-h`, `-Help`, and PowerShell's standard `-?` display help without opening setup or performing an operation. All six examples explain their scenarios and effects. Custom help aliases use compact spacing; `-?` retains PowerShell's native formatting.
- **Refreshed native controls:** Embedded application branding, Windows-style command and field icons, accessible tooltips, and enlarged-font layouts. Ctrl+Backspace deletes words without inserting control characters and retains native undo.
- **Animated space background:** Original, locally rendered stars are scattered across a dark sky and drift steadily, with no spiral or orbital motion. They keep moving even when the mouse is outside the window or another application has focus, with gently eased parallax when the mouse is inside. The **Motion** checkbox pauses animation, as do hiding, minimizing, or resizing setup. Reduced-motion and remote-session settings keep the scene still; high contrast removes it.

## Fixes and hardening

- UI types now load under source-versioned namespaces, preventing an older assembly in a persistent PowerShell session from hiding newly added controls such as `IconCheckBox`.
- Strict JSON numeric grammar rejects malformed numbers that the platform reader otherwise accepts.
- Unavailable Favorites addresses have bounded, sanitized display text and remain ineligible for import; browser files are not modified.
- Icon previews and editor reset, cancellation, address changes, disposal, and enlarged-text scrolling have regression coverage.
- Large HTML pages can supply declared icons within their first 512 KiB. Static SVG paths and gradients are rendered locally with pinned embedded dependencies; scripts, CSS, external resources, and excessive SVG complexity are rejected.

## Upgrade and download

Download `EasyEdgeApps.ps1` from this release's assets. It is the only runtime file required. Close the old setup window and run the updated script as the Windows user whose shortcuts you manage. Existing saved apps, shortcuts, version-1 App Kits, and older command-line operations remain compatible; there is no data migration or automatic script updater. Newly saved HTTP apps and kits require version 1.2.0 or later.

`SHA256SUMS.txt` contains the script's SHA-256 checksum. Compare it with `Get-FileHash .\EasyEdgeApps.ps1 -Algorithm SHA256`. The script is unsigned; a matching checksum detects a mismatched download, not publisher identity or code safety.

Windows PowerShell 5.1 and PowerShell 7 on Windows are supported. No elevation, external modules, browser-policy changes, services, or background launcher are required. These remain Edge app-window shortcuts, not fully registered Progressive Web Apps.

## Privacy and limits

**Get icon** is opt-in network access to the entered website and its declared icon or redirect destinations, with normal certificate validation. Missing schemes submitted through setup use credential-free HEAD probes. HTTPS requests do not downgrade to HTTP; resolved or explicit HTTP destinations are unencrypted. It uses no third-party favicon service, browser cookies, stored passwords, default Windows/proxy credentials, authorization header, or referrer. A website can direct requests to other hosts reachable from the computer; use trusted sites and never enter URLs containing secrets. Typing, starting setup, importing kits, and checking apps do not retrieve icons automatically.

HTML discovery reads a bounded 512 KiB prefix. Image downloads have no fixed file-size cutoff and use automatically deleted temporary files; available disk space and decoder resources still apply. Images become Windows-compatible, aspect-preserving 128-pixel ICOs before explicit saving. Redirect counts, network cancellation deadlines, malformed-image validation, and static-SVG complexity checks remain in place. Synchronous decoding is not a forcibly terminated sandbox. Sign-in-protected sites and unsupported SVG features may still require a trusted local `.ico` file. SVG.NET, ExCSS, and required compatibility assemblies and license notices are embedded, with no runtime package downloads.

**Encrypted exports remain experimental and require independent security review before production use.** Encryption protects only the exported file, not installed settings, shortcuts, recovery files, or browser sessions. Known-answer and tamper tests are not an independent cryptographic audit. Keep credentials out of URLs and notes, and share strong passphrases separately.

Ownership, preflight, per-app staging, locking, and caught-error rollback remain in place. A whole kit is not one atomic transaction; earlier successes can remain after a later failure. Check and Repair does not verify website access or repair sign-in.

## Verification

Ten isolated suites cover shortcut ownership and rollback, JSON portability and bounds, Favorites, HTTPS-first resolution and HTTP portability, favicon discovery and large raster/static SVG conversion, temporary-file cleanup, real background workers and cancellation, App Kits and repair, cryptographic vectors, encrypted-file interoperability, public CLI binding, and both native GUI surfaces. The runner covers Windows PowerShell 5.1 and PowerShell 7, including 12-, 18-, and 24-point layouts within 1024 by 768, spinner animation and cleanup, stale save intent, stale UI-assembly reloads, scattered-star pixel coverage, visible drift within one second, and animation without mouse input or window focus.

Live public-site favicon retrieval is also checked separately from the deterministic offline suite. Real-site sign-in, physical high-DPI/high-contrast/Narrator use, cross-computer handover, and OneDrive/network-filesystem behavior still require acceptance checks on the intended computers. See the README, automation guide, security guidance, and App Kit specification for details.
