# Easy Edge Apps 1.4.0

Author: Blake Drumm (blakedrumm@microsoft.com)

Adds per-website window preferences, a separate persistent profile by default for new apps, and protection for unsaved setup changes. Existing shared-profile websites are not silently converted. Normal Edge sign-ins, cookies, and other browser data are never copied or cleared.

## Window controls

- **Remember last size**, the new default, restores usable size, position, and maximized state for owned separate-profile and Fresh windows. Placement is stored outside browser data, fitted to an available monitor working area, and never restores minimized or fullscreen bounds.
- **Maximized** requests a maximized window on each new launch.
- **Full screen** fills the monitor; unmodified **Escape** exits the owned foreground fullscreen window. The next launch still follows the saved Full screen choice. This is not kiosk mode.
- **Always on top** is a setup checkbox for remembered-size and maximized windows. It is disabled for native Edge fullscreen because those modes cannot reliably be combined. No right-click commands are injected into Edge.
- Reopening an already running persistent app focuses its existing window without resetting a size the user just changed. Each Fresh launch remains independent.

Window management requires an owned separate or Fresh profile. Shared-profile shortcuts still launch normal Edge directly; Edge manages their placement. The Escape hook passes original input through, records no keys, and rechecks exact job ownership, fullscreen state, modifiers, and foreground before sending F11. A startup fallback handles Escape before the first window-discovery timer tick. Native foreground/input races and hook scheduling remain platform limitations.

## Profiles and compatibility

New apps and newly imported websites default to **Separate app profile**, **Remember last size**, Fresh off, Taskbar off, and Always on top off. Turn off Separate app profile explicitly to use normal Edge. Taskbar requires both the Start menu entry and the separate-profile route, even when Fresh is enabled. Turning Taskbar off does not implicitly clear the separate-profile choice in schema-4 apps.

Local schema 4 records the profile route and window preferences. Schemas 1/2/3 retain their existing effective choices until the new settings are explicitly supplied; merely installing the manager does not convert them. Schema-4 data requires 1.4.0 or later. Portable App Kit formats remain schemas 1/2 and never include profile routes, window preferences, geometry, or pins. Import and Repair preserve destination-local choices. Browser data is retained after opt-out, removal, and MSI maintenance.

## Setup and safeguards

- New, selection, import/maintenance tools, and Close ask before discarding a changed draft and default to keeping it. Successful saves establish a clean baseline.
- Status and activity controls emit native accessibility name/value and state/description notifications in both PowerShell hosts, including the return to idle. Actual spoken screen-reader output remains an acceptance check.
- Editor access keys are unique. Replaced fonts are disposed after controls receive the replacement, and setup refits on working-area changes without repeatedly moving an unchanged layout.
- ICO conversion chooses the smallest adequate frame instead of decoding an unnecessary larger frame.
- Missing settings never authorize adoption of a nonempty retained app folder. Import approval binds the complete reviewed kit definition, not just its name and URL.
- [Support information](../../tools/Get-SupportInfo.ps1) reports an allowlisted local environment summary without enumerating saved apps or browser data. [Publisher verification](../../tools/Test-PublisherSignature.ps1) fails closed unless every supplied file has a valid, timestamped Authenticode signature from the expected signer. It does not sign files or make this unsigned release trusted.

## Upgrade existing websites

1. Close website windows and the manager, then install **EasyEdgeApps-1.4.0-x64.msi**, or replace the portable script.
2. Open **Check apps...**, select repairable websites, and approve **Repair Selected** to rebuild outdated owned launchers. Installing the MSI alone does not update per-website executables.
3. Select an existing website and explicitly save the desired profile and window choices. Legacy shared apps remain shared unless conversion is approved; sign in separately inside a new dedicated profile.
4. Unpin old taskbar entries that target Edge directly, then save with **Taskbar** selected and approve Windows' pin request. Existing pins otherwise bypass the new launcher controls. Clearing Taskbar or removing a website never silently unpins it.

There is no need to remove and recreate existing websites. Retained browser data is not a backup of missing settings; restore trusted settings or use another name when Check reports an ambiguous nonempty folder.

## Verification and limits

All 18 application suites passed in Windows PowerShell 5.1 and PowerShell 7, for **36 local suite runs**. Native GUI coverage includes 12/18/24-point text within 1024 by 768, draft protection, mnemonic uniqueness, font disposal, work-area fitting, and exact accessibility event IDs. A deliberately wrong activity event failed the new regression before restoration.

Real Edge acceptance verified remembered bounds, topmost persistence and opt-out, maximized launch, fullscreen, Escape, and owned-job shutdown in both Fresh and persistent modes. A test-only launcher with discovery disabled proved the initial Escape path; disabling that ownership fallback made the regression fail at Escape exit. One earlier shutdown timeout was recorded; subsequent focused and both-mode runs completed. This is local evidence, not a guarantee on every Windows configuration.

The separate browser-data checks also passed: three Fresh launches had independent empty cookies/storage/cache and owned-profile cleanup; three persistent launches retained that data and reused an already running app window. These checks use only a synthetic loopback site and disposable profiles.

The pinned WiX 5.0.2 build and both-host MSI structural checks passed without installing over the existing local application. Release gates additionally require main/tag CI and disposable hosted installer lifecycle tests against a synthetic predecessor and the authentic published 1.3.2 and 1.3.3 MSIs, including folder retention, repair, downgrade rejection, and uninstall preservation. The released MSI must be the exact retained CI artifact. Final run URLs and asset hashes accompany the release in **VALIDATION.md** and **SHA256SUMS.txt**.

The script, manager, MSI, and generated launchers remain **unsigned** because no trusted publisher identity is available. Password-protected App Kits remain **experimental** pending independent cryptographic review. Physical screen-reader, mixed-DPI/4K input, managed-policy, real-site authentication, locale, ARM64, and cross-computer acceptance are not established by the automated suite. Same-user filesystem races, native image-decoder/resource limits, foreground races, and crash or locked-file cleanup limits are not sandbox guarantees.
